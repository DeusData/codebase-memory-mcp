# RFC 002: `get_api_surface` — Ingress Routes & Egress External Service Contract Catalog

- **RFC Number:** 002
- **Title:** `get_api_surface` — Ingress HTTP/RPC Routes & Egress External Service Catalog
- **Status:** Proposed
- **Author:** Codebase Memory Architecture Team
- **Target Subsystem:** `src/mcp/`, `src/store/`, `src/cli/`, `graph-ui/`
- **Target Version:** v0.12.0
- **Created:** 2026-10-04

---

## 1. Executive Summary & Problem Statement

### 1.1 The Problem
When joining or inspecting an unfamiliar backend, microservice, or full-stack application, an engineer or AI assistant's immediate questions are:
1. **What external API endpoints does this service expose?** (HTTP routes, WebSocket endpoints, gRPC procedures).
2. **Which handler function and source file implement each route?**
3. **What third-party or downstream external HTTP services, message queues, and brokers does this application invoke?**
4. **How are requests routed through middleware to the underlying domain and database models?**

Currently, `codebase-memory-mcp` indexes `Route` nodes and extracts `HTTP_CALLS` / `ASYNC_CALLS` edges during AST analysis (`src/pipeline/pass_route_nodes.c`), but **there is no dedicated MCP tool to query this catalog**.
- Routes and endpoints are mixed anonymously with 20,000+ general code symbols.
- An AI agent must manually construct raw Cypher queries like `MATCH (r:Route) ...` or resort to searching file names like `routes.ts` or `controller.go`.
- External HTTP egress calls (e.g. calls to Stripe, GitHub API, AWS S3) and message brokers (RabbitMQ, Kafka, BullMQ) are completely opaque unless inspected by reading raw source code.

### 1.2 The Solution
Introduce the `get_api_surface` tool.
This tool produces a structured catalog of both:
- **Ingress Endpoints**: All public and internal API routes exposed by the application, mapped to their HTTP method, route pattern, handler function, file location, and parameter schemas.
- **Egress External Calls**: All external HTTP/RPC endpoints and message queues invoked by the codebase, including client library used (Axios, Fetch, cURL, Requests), base URLs, brokers, and calling functions.

The SQLite database already contains:

```

                       ▼
       ┌───────────────────────────────┐
       │   Node: label = 'Route'       │
       │   properties: {               │
       │     "url_path": "/api/users", │
       │     "method": "POST",         │
       │     "broker": "http"          │
       │   }                           │
       └───────────────┬───────────────┘
                       │ (HANDLES / CALLS)
                       ▼
       ┌───────────────────────────────┐
       │   Node: label = 'Function'    │
       │   name: "create_user_handler" │
       │   file: "src/api/users.c"     │
       └───────────────┬───────────────┘
                       │
                       │ (HTTP_CALLS / ASYNC_CALLS)
                       ▼
       ┌───────────────────────────────┐
       │   Edge: type = 'HTTP_CALLS'   │
       │   properties: {               │
       │     "url_path": "/v1/charges",│
       │     "http_client": "stripe",  │
       │     "http_base_url": "api.com"│
       │   }                           │
       └───────────────────────────────┘
                       │
                       ▼
               [Egress Request]
```

- **`Route` Nodes (64 currently in DB)**: Generated by `pass_route_nodes.c` across Express, FastAPI, Flask, Actix, Gin, Spring, and C HTTP servers.
- **`HTTP_CALLS` Edges (93 in DB)**: Capturing outbound HTTP client requests.
- **`ASYNC_CALLS` Edges**: Capturing pub/sub messaging patterns.
- **`CROSS_HTTP_CALLS` Edges**: Inter-service edges connecting multi-repo projects.

## 3. Tool Specification (MCP JSON-RPC)

### 3.1 Tool Registration
- **Name:** `get_api_surface`
- **Description:** Returns the complete API contract surface of a codebase, including ingress HTTP/RPC endpoints (routes, methods, controller handlers) and egress third-party HTTP calls, webhooks, and message broker queues.

### 3.2 Input Parameters (`inputSchema`)

```json
{
  "type": "object",
  "properties": {
    "project": {
      "type": "string",
      "description": "Target project identifier registered in Codebase Memory."
    },
    "direction": {
      "type": "string",
      "enum": ["all", "ingress", "egress"],
      "default": "all",
      "description": "Filter by API direction: ingress (incoming routes), egress (outbound client calls), or all."
    },
    "method": {
      "type": "string",
      "enum": ["ALL", "GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS", "HEAD", "WS"],
      "default": "ALL",
      "description": "Optional HTTP method filter."
    },
    "path_pattern": {
      "type": "string",
      "description": "Optional regex or substring to filter route URLs (e.g. '/api/v1/*')."
    },
    "group_by": {
      "type": "string",
      "enum": ["flat", "file", "method", "service"],
      "default": "flat",
      "description": "Grouping layout for response: flat list, grouped by source file, or grouped by domain service."
    }
  },
  "required": ["project"]
}
```

## 4. Query & C Implementation Architecture

### 4.1 Ingress Routes SQL (`src/store/store.c`)

```sql
SELECT 
    r.id AS route_node_id,
    coalesce(json_extract(r.properties, '$.method'), 'ANY') AS http_method,
    coalesce(json_extract(r.properties, '$.url_path'), r.name) AS url_path,
    coalesce(json_extract(r.properties, '$.broker'), 'http') AS broker,
    r.file_path,
    r.start_line,
    h.name AS handler_name,
    h.qualified_name AS handler_qn,
    h.file_path AS handler_file,
    h.start_line AS handler_line,
    json_extract(h.properties, '$.docstring') AS handler_doc
FROM nodes r
LEFT JOIN edges e ON (e.source_id = r.id AND e.type IN ('CALLS', 'HANDLES', 'DEFINES_METHOD'))
LEFT JOIN nodes h ON e.target_id = h.id
WHERE r.project = ?1 
  AND r.label = 'Route'
ORDER BY url_path ASC, http_method ASC;
```

### 4.2 Egress Calls SQL

```sql
SELECT 
    c.id AS caller_node_id,
    c.name AS caller_name,
    c.qualified_name AS caller_qn,
    c.file_path AS caller_file,
    c.start_line AS caller_line,
    e.type AS edge_type,
    json_extract(e.properties, '$.url_path') AS url_path,
    json_extract(e.properties, '$.method') AS method,
    json_extract(e.properties, '$.http_client') AS http_client,
    json_extract(e.properties, '$.http_base_url') AS http_base_url,
    json_extract(e.properties, '$.broker') AS broker
FROM edges e
JOIN nodes c ON e.source_id = c.id
WHERE e.project = ?1
  AND e.type IN ('HTTP_CALLS', 'ASYNC_CALLS', 'CROSS_HTTP_CALLS', 'CROSS_ASYNC_CALLS')
ORDER BY c.file_path ASC, c.start_line ASC;
```

## 5. CLI & UI Integration

### 5.1 CLI Command
```bash
# List all ingress and egress endpoints
cbm cli get_api_surface --project codebase-memory-mcp-ui

# Inspect only POST routes
cbm cli get_api_surface --project codebase-memory-mcp-ui --direction ingress --method POST
```

### 5.2 UI Integration (`graph-ui`)
- **Dedicated Section in DiagramsTab & ToolsTab**:
  - Filterable API table: `[Method Badge] [URL Pattern] [Handler Link] [Egress Deps]`.
  - Visual OpenAPI/Swagger-like interactive explorer synthesized directly from graph data.
  - Clicking any route jumps directly to the AST code viewer in `NodeDetailPanel`.
